{%- comment -%} Structured data for the publication list, generated from the same _data/publications.yml the cards are rendered from, so the two cannot drift apart. One @graph of ScholarlyArticle nodes rather than a script per paper: fewer blocks, and it keeps the whole bibliography as a single addressable set. Every value goes through `jsonify`, which escapes quotes and newlines — abstracts contain both. Journal/volume/issue use the schema.org nesting convention: PublicationIssue -> PublicationVolume -> Periodical Papers with no volume (the conference proceedings here) fall back to the Periodical alone. {%- endcomment -%} {%- comment -%} Takes the already-sorted list so the graph matches the order of the rendered cards; falls back to the raw data file if included without the parameter. {%- endcomment -%} {%- assign publications = include.publications | default: site.data.publications -%}
